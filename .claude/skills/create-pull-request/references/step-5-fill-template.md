# Step 5 — Fill the Template

Use the collected context to fill every section of the chosen template:

- **Description**: Explain _what_ changed and _why_, in plain language.
- **Type of Change**: Check the box(es) that fit best.
- **Changes Made**: List the real changes, taken from the git diff / plan.
- **How to Test**: Write clear steps a reviewer can follow.
- **Checklist**: Check only the items you can prove are done. Leave the other items unchecked for the developer to confirm.
- **Related Issues**: Insert ticket/issue references (e.g., `Closes #123`).
- **Screenshots**: Say if screenshots are not needed, or ask the user to add them.

Do **not** leave placeholder comments empty if you have enough context to fill them.

Do **not** add any AI/agent attribution to the description — no "Generated by", "Created by Claude", "Co-Authored-By: Claude", or similar tool/author signature lines. Write the description as the developer's own.
