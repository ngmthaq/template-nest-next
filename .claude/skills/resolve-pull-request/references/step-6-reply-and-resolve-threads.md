# Step 6 — Reply to and Resolve Threads

When party-mode's review has **accepted** the changes for a comment, push the branch. Then reply to and resolve that comment's thread.

## Push the changes first

```bash
git push           # push the accepted commits to the PR head branch
```

Replies should point to work that people can already see on the PR, so push before you reply.

## Reply, then resolve — per accepted thread

For each `resolve` row whose change was accepted, post a short reply that says **what changed** (and the commit/file if useful). Then mark the thread resolved. For `reply-only` rows (questions), post the answer. Resolve the thread only if it really needs no code change.

Do **not** add any AI/agent attribution to the reply — no "Generated by", "Resolved by Claude", "Co-Authored-By: Claude", or similar signature lines. Each reply has only the useful content.

## Using MCP

Use the MCP tool to reply to each thread by its ID and to mark it resolved.

## Using the CLI

**GitHub** — reply to the review comment, then resolve the thread with GraphQL (you need the thread node ID from Step 3):

```bash
# Reply to an inline review comment (by its REST comment id)
gh api repos/{owner}/{repo}/pulls/{number}/comments/{comment_id}/replies \
  -f body="<what changed>"

# Resolve the thread (thread node id from the reviewThreads query in Step 3)
gh api graphql -f query='
  mutation($threadId:ID!){
    resolveReviewThread(input:{threadId:$threadId}){ thread{ isResolved } } }' \
  -F threadId=<thread-node-id>
```

**GitLab** — add a note to the discussion, then resolve it:

```bash
glab api projects/:id/merge_requests/<number>/discussions/<discussion_id>/notes \
  -f body="<what changed>"

glab api --method PUT \
  "projects/:id/merge_requests/<number>/discussions/<discussion_id>?resolved=true"
```

**Bitbucket** — use the installed CLI's reply / resolve commands (flags are different for each tool). If the CLI cannot resolve a thread, post the reply and tell the user to resolve the thread by hand.

## Do not resolve when

- The change was not accepted by party-mode's review (`incomplete` / `blocked`).
- The comment was a question the user has not yet answered.
- You could not link the change to that exact comment.

Leave those threads open and report them in Step 7.
