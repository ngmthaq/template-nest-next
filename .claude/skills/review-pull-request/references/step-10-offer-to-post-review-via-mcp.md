# Step 10 — Offer to Post Review (File + Line Comments)

After you show the report, ask:

> _"Should I post these findings as file + line comments on PR #[number]?"_

Each finding is posted as an **inline comment on an exact file and line**. Do **not** post a general PR-level / summary comment — every comment must point to a file + line.

```markdown
Review Comments:

| File           | Line | Comment                                                                                        |
| -------------- | ---- | ---------------------------------------------------------------------------------------------- |
| `file.ts`      | 42   | "SRP violation: this function does too much. Need to refactor into smaller functions."         |
| `file.ts`      | 88   | "Avoid interpolating user input directly into SQL queries. Use parameterized queries instead." |
| `file.spec.ts` | 40   | "AAA violation: test name describes implementation details rather than behavior."              |
```

If a finding does not point to a real file + line, skip it. Do not turn it into a general comment.

Do **not** add any AI/agent attribution to the comment body — no "Generated by", "Reviewed by Claude", "Co-Authored-By: Claude", or similar tool/author signature lines. Each comment has only the finding.

## Posting via MCP

If the user says yes, use the MCP tool to post each finding as a **line review comment** on its file and line. If the MCP supports it, post one **review** with all inline comments instead of separate comments. Never post a top-level PR comment.

## Posting via CLI

If only a CLI is available, post one inline comment per finding with the platform's API command. These commands need the file path, line, and (for GitHub) the head commit SHA.

**GitHub** — use the REST API through `gh` for line comments (plain `gh pr comment` posts a PR-level comment, so do **not** use it here):

```bash
gh api repos/{owner}/{repo}/pulls/{number}/comments \
  -f body="<comment>" \
  -f commit_id="<head-sha>" \
  -f path="<file>" \
  -F line=<line> \
  -f side="RIGHT"
```

Get the head SHA with `gh pr view <number> --json headRefOid -q .headRefOid`.

**GitLab** — post a discussion on a diff line:

```bash
glab api projects/:id/merge_requests/<number>/discussions \
  -f body="<comment>" \
  -f "position[position_type]=text" \
  -f "position[new_path]=<file>" \
  -f "position[new_line]=<line>" \
  -f "position[base_sha]=<base-sha>" \
  -f "position[head_sha]=<head-sha>" \
  -f "position[start_sha]=<base-sha>"
```

**Bitbucket** — use the installed CLI's inline-comment command (flags are different for each tool). It must take a file path and line number. If the CLI cannot put a comment on a file + line, do not post a general comment — show the findings to the user as the table above instead.

After posting, tell the user how many inline comments you created and give the PR/MR URL.
