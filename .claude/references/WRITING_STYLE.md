# WRITING STYLE

Many users and developers are not strong in English. Everything an agent writes must be easy to read with basic English. This covers chat messages, questions, explanations, plans, delegation prompts, reviews, reports, and generated docs.

---

## DO

- DO: use short sentences — one idea per sentence.
- DO: use common, everyday words. Prefer "use" over "leverage", "check" over "validate", "change" over "modify", "show" over "surface", "split" over "decompose", "start" over "initiate", "about" over "regarding", "enough" over "sufficient".
- DO: explain less common technical terms in a few words the first time. Common ones (API, cache, token, migration, …) are fine.
- DO: prefer bullet points and tables over long paragraphs.
- DO: use active voice: "The API returns an error", not "An error is returned by the API".
- DO: get to the point. Say what happened or what is needed first, then the details.

---

## DO NOT

- DON'T: use idioms, slang, or fancy phrases (e.g. "low-hanging fruit", "boil the ocean", "holistic", "synergy", "robust", "seamless").
- DON'T: write long paragraphs when a short list works.
- DON'T: repeat the same point in different words.
