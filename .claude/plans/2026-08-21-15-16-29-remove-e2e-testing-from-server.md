# Title: Plan — Remove E2E Testing from the Server App

- Classification: feature
- Description: Delete the server app's unused end-to-end test scaffold — spec directory, jest config, npm script, `supertest` dependencies, and the two config references — leaving the colocated unit-test setup untouched.

---

## Approach Summary / Goal

- The server's e2e setup is the stock NestJS scaffold and carries no value: `apps/server/__e2e__/app.e2e-spec.ts` contains a single empty `describe` block with every meaningful line commented out. Nothing in CI, husky, or Docker invokes `pnpm test:e2e`.
- Removal is therefore a pure subtraction — delete the artifacts, then clean the two config files that reference `__e2e__` by path so no dangling references remain.
- `supertest` and `@types/supertest` are removed because the (commented-out) e2e spec was their only consumer. `@nestjs/testing` is **kept** — `src/feature/cache/cache.service.spec.ts` imports it for unit testing.
- Goal: `apps/server` has zero e2e footprint, while `pnpm server build`, `pnpm server lint:check`, and `pnpm server test` (12 colocated spec files) all continue to pass.

## Functional Requirements

- `apps/server/__e2e__/` no longer exists.
- `apps/server/jest-e2e.json` no longer exists.
- The `test:e2e` script is absent from `apps/server/package.json`; the other four test scripts (`test`, `test:watch`, `test:cov`, `test:debug`) are unchanged.
- `supertest` and `@types/supertest` are absent from `apps/server/package.json` devDependencies; every other dependency is unchanged.
- `pnpm-lock.yaml` is regenerated so it matches the updated `package.json`.
- `apps/server/tsconfig.build.json` `exclude` no longer lists `"__e2e__"`, and still lists `"node_modules"`, `"dist"`, `"src/generated"`, `"**/*spec.ts"`.
- The `**/__e2e__` line is removed from the root `.dockerignore`; `**/__test__` and all other entries stay.
- `grep -rn "e2e\|supertest"` over `apps/server` (excluding `node_modules`/`dist`/`coverage`) returns no hits.

## Non-Functional Requirements

- No change to runtime/production code under `apps/server/src`.
- No change to the unit-test configuration (`apps/server/jest.config.json`) or to any of the 12 `src/**/*.spec.ts` files.
- JSON files keep their existing formatting (2-space indent, Prettier-clean).
- `apps/client` is not touched.

## Files in Scope

- `apps/server/__e2e__/app.e2e-spec.ts` — **deleted**
- `apps/server/__e2e__/` — **deleted** (directory)
- `apps/server/jest-e2e.json` — **deleted**
- `apps/server/package.json` — modified (drop `test:e2e` script, drop `supertest` + `@types/supertest`)
- `apps/server/tsconfig.build.json` — modified (drop `"__e2e__"` from `exclude`)
- `.dockerignore` — modified (drop `**/__e2e__`)
- `pnpm-lock.yaml` — regenerated by `pnpm install`

## Risks & Assumptions

- **Assumption:** the e2e scaffold is genuinely unused. Verified — its only spec is fully commented out, and a repo-wide grep found no CI workflow, husky hook, or Docker step invoking `test:e2e`.
- **Assumption (from user answers):** full removal including dependencies and config references, with the lockfile regenerated.
- **Risk (low):** `pnpm install` regenerates `pnpm-lock.yaml` and may produce a diff larger than the two removed packages if any transitive resolution shifts. The developer must report the lockfile diff size rather than silently accept it.
- **Risk (low):** `apps/client/tsconfig.tsbuildinfo` matched the e2e grep — it is a generated build cache in `apps/client`, out of scope and intentionally not touched.
- **Note:** `docs/2026-08-20-11-18-11-colocate-server-unit-tests-with-source-files.md` references `__e2e__` as a historical record of a past plan. It is deliberately **not** edited — amending a completed plan document would falsify the project history.
- **Risk (none expected):** re-adding e2e later means re-running `nest new`-style scaffolding by hand; this is a deliberate, reversible removal.
